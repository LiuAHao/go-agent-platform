# ADR-002: Local-first Execution with Cloud Registry

## Status

Accepted

## Context

项目目标是面向普通用户提供 Agent 创建、能力装配和对话执行能力。早期曾考虑全云端 Agent 平台，但 Skill、MCP、本地文件、浏览器、命令行和模型 API Key 都存在明显的本地执行诉求。

如果所有任务都放到云端执行，平台必须提前解决多租户隔离、用户密钥托管、文件访问授权、运行沙箱、任务审计和资源成本问题。这会显著增加 MVP 落地难度。

## Decision

首版采用“云端 Registry + 本地运行时”的架构：

- 云端负责账号、平台 Skill/MCP/Agent 模板目录、版本管理、资源下载和管理后台
- 桌面客户端负责用户主要工作流，包括创建 Agent、配置模型、安装资源和进入聊天
- 本地运行时负责 Agent 执行、模型调用、Skill/MCP 调用、本地存储和本地权限控制
- Web 只作为官网、登录注册、资源浏览和客户端下载入口，不作为完整执行端

## Consequences

- 优点：更容易访问本地资源，用户密钥默认留在本机，MVP 实施成本更低
- 优点：云端可以专注资源供给和版本分发，避免过早承担任务执行成本
- 缺点：需要维护桌面客户端和本地运行时，安装、更新和兼容性复杂度更高
- 缺点：移动端短期只能作为伴侣端，不能完整替代桌面端

## Follow-up

- 补齐云端管理面板，用于平台资源上架、版本和用户管理
- 把代码边界拆成 cloud、local、runtime、shared 四类模块
- 为平台资源增加签名、校验和版本元数据
- 为本地运行时增加权限控制和敏感配置本地存储
